# 단디 DANDI, 금융 AI 개인정보 보호 게이트웨이 프로토타입

> 이 저장소는 검수된 고정 합성 사례만 실행하는 브라우저 기능형 프로토타입입니다. 실제 또는 가명 고객정보, 서버, 외부 AI, 데이터베이스, 로그인·인증, 실제 금융 판단은 포함하지 않습니다. 실제 제품 성능이나 운영 보안을 검증한 결과도 아닙니다.

단디는 금융 직원의 상담 메모에서 합성 식별정보를 찾고 유형에 맞게 보호한 뒤, 로컬 모의 요약의 전체 응답을 검사해 확인된 결과만 보여주는 흐름을 설명합니다. 화면 연출만 재생하는 방식이 아니라, 세 고정 사례가 같은 TypeScript 파이프라인을 실제로 통과합니다.

- 시연 화면: [wannahappyaroundme.github.io/privacy-gateway-demo](https://wannahappyaroundme.github.io/privacy-gateway-demo/)
- 공개 소스: [github.com/wannahappyaroundme/privacy-gateway-demo](https://github.com/wannahappyaroundme/privacy-gateway-demo)

## 바로 실행하기

필요한 버전은 Node.js `20.19.5`, npm `10.8.2`입니다.

```bash
npm ci --ignore-scripts --no-audit --no-fund
npx playwright install chromium
npm run dev
```

터미널에 표시된 로컬 주소를 브라우저에서 엽니다. `합성 사례 선택`에서 사례를 고른 뒤 `개인정보 보호 후 요약 만들기`를 누르면 탐지, 보호, 로컬 모의 요약, 전체 검사, 결과 공개 또는 중단이 이어집니다.

## 세 가지 고정 합성 사례

세 사례는 사례 ID별로 결과를 미리 고르는 별도 코드가 아니라, 모두 `src/prototype/run.ts`의 같은 실행 순서를 따릅니다.

| 사례 | 입력의 차이 | 실행 결과 |
| --- | --- | --- |
| `SYN-NORMAL-001` 정상 상담요약 | 합성 이름·연락처·계좌가 포함됨 | 유형별 보호와 전체 검사를 통과한 다섯 개 업무 항목만 공개 |
| `SYN-BLOCK-001` 요청 단계 차단 | 지원 범위 밖인 합성 인증정보가 포함됨 | 보호된 요청을 만들기 전에 중단, 로컬 모의 요약 호출 0회 |
| `SYN-WITHHOLD-001` 결과 미공개 | 로컬 모의 응답이 계좌 보호용 표시를 바꿈 | 전체 검사에서 표시 변경을 확인하고 결과를 공개하지 않음 |

합성 문장은 실제 또는 가명 기록을 변형하지 않고 이 공개 시연을 위해 처음부터 작성했습니다. 자유 입력과 파일 업로드는 제공하지 않습니다.

## 브라우저에서 실제로 실행하는 단계

1. **합성 정보 찾기**: 이름, 연락처, 계좌, 지원 범위 밖 인증정보를 고정된 합성 문법으로 찾습니다.
2. **유형별 보호**: 이름은 요청별 가상값으로 바꾸고, 연락처와 계좌는 원문이 없는 유형 표식으로 바꿉니다. 인증정보가 있으면 다음 단계로 보내지 않습니다.
3. **로컬 모의 요약**: 보호된 문장만 결정형 TypeScript 요약기에 전달합니다. 실제 AI나 외부 API는 사용하지 않습니다. 응답은 여러 조각으로 나누어 돌아오는 상황을 재현합니다.
4. **전체 응답 검사**: 응답 조각을 다시 합친 뒤 출력 형식, 보호용 표시, 합성 원문 잔존, 입력 문장 근거, 금융 판단 제외 여부를 차례로 확인합니다.
5. **검사 뒤 공개**: 모든 검사를 통과한 경우에만 허용된 다섯 개 업무 항목을 정확히 복원해 보여줍니다. 실패하면 결과를 잠그고 다음 행동을 안내합니다. 실행이 끝나면 요청 안에서 사용한 연결표를 비웁니다.

## 구현 범위

### 이 프로토타입에서 실행하고 확인하는 것

- 검수된 합성 사례 3개와 하나의 실제 TypeScript 실행 파이프라인
- 이름·연락처·계좌의 유형별 보호와 지원 범위 밖 인증정보 차단
- 결정형 로컬 모의 요약과 여러 응답 조각의 전체 재조립
- 출력 형식, 보호용 표시, 원문 잔존, 입력 근거, 금융 판단 제외 검사
- 검사 완료 전 결과 미공개, 성공 시 정확 복원, 실패 시 명시적 중단
- 원문 없는 실행 근거 화면과 성공·실패 뒤 다음 행동
- 자동 테스트에서 관찰한 앱 외부 요청 0건과 브라우저 저장소 쓰기 0건

### 포함하거나 검증하지 않은 것

- 실제 또는 가명 고객정보 처리
- 서버 API, 데이터베이스, 로그인·권한 관리, 관리자 화면
- 실제 로컬 AI나 외부 AI, 한국어 개체 인식 모델
- 은행 내부망 설치, 온프레미스 운영, 실제 은행 시스템 연동
- 실제 금융 추천·승인·가격·한도 판단
- 실제 데이터 기준 탐지율, 처리 속도, 비용 절감, 규정 준수, 운영 보안

따라서 이 프로토타입의 결과를 실제 제품의 탐지 성능이나 금융회사 운영 통제의 달성 결과로 확대해서 해석하지 않습니다.

## 검증하기

전체 검증은 아래 명령으로 실행합니다.

```bash
npm run verify
```

이 명령은 타입, 코드 규칙, 단위 테스트, 빌드, 브라우저 동작, 접근성, 시각 기준, 녹화 흐름, 공개 파일 경계, 합성 데이터, 문구, 외부 요청·저장 경계, 라이선스 고지를 확인합니다. 테스트 개수는 코드와 함께 달라질 수 있으므로 README에 고정 수치를 적지 않습니다.

기능형 프로토타입의 소스 경계 검사는 `src/prototype`의 검수된 5개 파일을 정확한 파일 목록, SHA-256, 가져오기 관계, 실행 연산 원장으로 잠급니다. 검수되지 않은 변경은 실패하며 새 검토와 원장 갱신이 필요합니다. 이는 현재 고정 구현을 보존하는 장치이며, 임의의 TypeScript 프로그램 동작이나 실행 중 값의 출처를 수학적으로 증명하는 장치는 아닙니다.

정확한 RGBA 비교에는 macOS에서 생성한 검토 기준 이미지를 사용합니다. Linux에서는 같은 화면의 구조, 크기, 상태 계약을 확인합니다.

화면 녹화용 고정 상태만 다시 확인하려면 아래 명령을 사용합니다.

```bash
npm run record:check
```

이 검사는 세 사례의 대표 상태, 요청 차단 시 모의 요약 호출 0회, 검사 실패 뒤 결과 잠금, 콘솔·실행 근거의 원문 비노출, 앱 외부 요청과 브라우저 저장소 쓰기를 확인합니다. 결과는 원문 없이 `artifacts/recording-check.md`에 기록됩니다.

## 외부 요청과 방문자 정보

자동 브라우저 테스트는 세 합성 사례를 실행하면서 앱이 만든 외부 요청과 브라우저 저장소 쓰기를 관찰하며, 현재 두 항목 모두 0건으로 확인합니다. 정적 화면에 필요한 문서, 스크립트, 스타일, 글꼴, 이미지는 같은 출처에서 읽습니다.

공개 시연은 GitHub Pages에서 제공됩니다. 방문 과정에서 GitHub가 접속 IP 등 방문 정보를 처리할 수 있으므로, 공개 운영 시 GitHub의 개인정보 처리 안내와 보존 정책을 함께 확인해야 합니다.

## 공개 배포 절차

GitHub Pages 배포는 자동으로 시작되지 않습니다. 아래 조건을 모두 갖춘 정확한 커밋만 수동으로 배포합니다.

1. 공개 후보에서 `npm run release:manifest`를 실행해 소스 해시와 제3자 고지를 갱신합니다. 소스가 달라지면 기존 공개 승인은 닫힙니다.
2. `npm run verify`를 실행해 같은 후보를 전체 검증합니다.
3. 소유자가 후보의 정확한 해시를 검토한 뒤 `release-manifest.json`에 별도 공개 승인 상태, 검토자, 승인 시각을 기록합니다.
4. 승인 기록을 포함한 후보를 보호된 `main`에 반영합니다.
5. GitHub Actions의 `Publish reviewed static demo`를 수동 실행하고, `approved_commit_sha`에 보호된 `main`의 소문자 40자리 전체 커밋 SHA를 입력합니다.
6. 워크플로가 현재 브랜치, 브랜치 보호, 입력 SHA와 실제 SHA의 일치, 전체 검증, 공개 승인 기록을 다시 확인한 뒤 검증된 정적 묶음만 Pages에 배포합니다.

배포 전에는 프리뷰 확인과 소유자의 명시적 승인이 필요합니다. 배포 결과와 검사 기록은 저장소의 Actions와 Pages에서 확인할 수 있습니다.
